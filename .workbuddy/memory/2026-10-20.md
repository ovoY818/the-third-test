## 全屏自适应缩放（transform: scale 方案）
- 用户要求画板等比缩放铺满屏幕且不动任何 left/top。注意：用户给的纯 CSS 片段 scale(calc(100vh/1024)) 无效——scale() 只接受无单位数字，100vh/1024 是长度，整个声明会被丢弃、画板会跳位，故未原样采用。
- 实现：styles.css 末尾 G 段——[class^="desktop-"] 改 position:absolute + left/top:50% + transform:translate(-50%,-50%) scale(var(--fit-scale,1))；7 个页面 <head> 各加内联脚本算 min(innerWidth/1440, innerHeight/1024) 写入 --fit-scale（resize/orientationchange 监听）。html/body 清 flex 改 block + overflow:hidden + 底色 #1a1a1a。
- 关键坑：导出样式 .desktop-N-XX 带 min-height:100vh，视口高 >1024 时（1080p、竖屏）会撑高画板、破坏百分比定位与背景裁切。必须在 G 段加 min-height:0 !important + max-height:1024px !important。
- 实测：1600x1024 scale=1；1280x800 scale=0.78125；1920x1080 scale=1.0547；1000x1400 scale=0.6944 上下黑边严格对称；按钮/标题实测坐标 = 设计稿坐标×缩放比+偏移，全部吻合；7 页无滚动条。
- 等比缩放的数学必然：屏幕宽高比 ≠ 1440/1024 时某一侧必有深色边（Letterbox），已向用户说明；彻底无黑边需非等比拉伸（会变形），未采用。

## desktop-1 按钮文字层级修复（J 段，用户指定代码原样追加）
- 用户诉求：text-4 文字被黑框（img.rectangle-1-3）盖住"灰蒙蒙"，要求文字 z:99999 + 框 z:10，不动坐标。
- 实测真相（重要）：改前文字本就未被盖——span.text-white computed = absolute/z:9999，elementFromPoint 与 elementsFromPoint 均显示 SPAN 在最顶层、IMG 次之。用户看到的"灰蒙蒙"极可能是浏览器缓存旧 CSS（本项目多次发生）。
- 结构机理：p.text-4 的唯一子元素 span 被早期用户代码（2184/2210 段）设为 position:absolute → 脱离文档流 → p 塌缩为 0x0；文字实际由 span 渲染，span 相对 p 以 left:50%/top:65% + translate(-50%,-50%) 锚定，视觉位置 = 按钮正中心。
- 权重实况：.text-4 的 z-index:99999 会被 .desktop-1-1 a.prototype-link p.text-4（0,3,1）的 z-index:10 压过（实测 p=z:10）；span 的 99999 在同段竞争中后置获胜生效（实测 span=z:99999）。因文字由 span 渲染，p 保持 z:10 无实际影响。
- J 段追加内容（styles.css 最底部，用户代码原样）：.text-4, .text-4 span { z-index:99999 !important; position:absolute !important }；.rectangle-1-3 { z-index:10 !important }。缓存戳 ?v=20261020d → e（7 页）。
